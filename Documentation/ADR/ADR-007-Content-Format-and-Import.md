# ADR-007: JSON content format, bundled library and question generation

Status: Accepted · 2026-11-04

## Context

Phases 3 to 6 ran on `SampleContent`, ten words hard-coded in Swift. Phase 7 needs a real library that non-developers can author and review (Korean, English, Khmer), that the app validates before use (PRD FR-C1, AC-10), that updates additively by id (FR-C2) and that records source and license per item (FR-C3). The learner is also the Khmer reviewer, so review state must be visible without a database field.

## Decision

**Format.** One `package.json` (format version, library version, default source) plus any number of part files holding `vocabulary`, `grammar` and `questions` arrays, merged in file-name order. Authoring shapes (`meaning: {en, km}`, options as plain strings, `answer` as an index) are decoded by `ContentFile` in Domain into the existing entities. Option ids are derived from position (`o1`...), which keeps the JSON short at the cost of a rule: never reorder options of a shipped question. Specification in `CONTENT_FORMAT.md`.

**Where it lives.** The library is copied into the Persistence resource bundle and loaded at launch by `BundledContent.load()`; `CoreDataContentStore.apply` then imports it only when `version` is newer than the installed manifest. The existing upsert-and-retire importer from Phase 3 is reused unchanged, so moving from the sample data (version 1, ids `vocab.sample.*`) to the library (version 2, ids `vocab.*`) retires the sample rows and keeps learner history readable. `SampleContent` stays in Persistence as a small fixture for tests and previews; the app no longer loads it.

**Validation is total.** Decoding collects every field issue, converts, then runs `ContentPackage.validate()` and throws once with the full list. The app does not catch the error: a bad bundle must not reach users, and `BundledContentTests` fails first in CI.

**Generated questions.** Vocabulary meaning questions are generated by `MeaningQuestionGenerator` (two per word, seeded Fisher-Yates over an FNV-1a hash of the question id) and committed as `questions/generated-meaning.json`. Generating at authoring time rather than at runtime keeps question ids and option order stable across app versions, which SM-2 schedules and attempts depend on, and lets the reviewer read the output. Grammar, sentence completion and reading questions are hand-written.

**Tooling.** `content-lint`, an executable target in the package, validates any content directory and regenerates the meaning questions. CI runs it and fails on a dirty tree so the generated file cannot drift from the vocabulary.

**Review state.** `review: pending | reviewed` per item is counted on load and surfaced in Settings (`ContentInfo`). It is never persisted; flipping it does not need a version bump.

## Consequences

- Content changes are a JSON edit, a version bump, a lint run and a test run. No Swift changes.
- Settings shows real version, counts, source and license instead of constants.
- Authored ids are permanent. Renaming an id retires the old item and creates a new one with no history.
- Level 1 and 2 only in this phase: 230 words, 40 patterns, 530 questions. TOPIK II levels and audio are later content work with no format change expected; a format change bumps `formatVersion` and needs a migration path in `ContentFile.load`.
- Khmer in the first library is machine-assisted and marked pending until reviewed.
