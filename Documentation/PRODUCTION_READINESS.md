## 2. Security changes

| # | Change | Why | Verified by |
|---|--------|-----|-------------|
| S1 | `URLSessionTransport` refuses HTTP redirects | A redirect would replay the `x-api-key` header to the `Location` host | `URLSessionTransportTests.testRedirectIsNotFollowed`; fails when the delegate is removed (mutation run) |
| S2 | Replies capped at 1 MB; no cookie store, URL cache or credential storage; TLS 1.2 minimum | Hostile or broken replies cannot exhaust memory; nothing persisted by the session | `testReplyOverLimitIsRejected` |
| S3 | Both SQLite stores opened with `FileProtectionType.completeUntilFirstUserAuthentication` (iOS) | Make data-at-rest protection explicit; `complete` would stop CloudKit background imports | iOS builds; existing migration and on-disk tests pass |
| S4 | Session history stores device class (`iPhone`, `iPad`, `Mac`), not the device or host name | The name usually contains the owner's name and was synced to iCloud; `ProcessInfo.hostName` can also block on a DNS lookup at launch | iOS and macOS builds |
| S5 | `--ui-testing` honoured in Debug builds only | A launch argument could switch a Release install to the in-memory key store and turn sync off | `strings` on the Release binary: no `ui-testing` |
| S6 | `ITSAppUsesNonExemptEncryption = false` | Only system HTTPS; avoids the export-compliance prompt per upload | Built `Info.plist` |
| S7 | CI fails on any remote Swift package or committed `Package.resolved`; `actions/checkout` pinned to `11bd719…` (v4.2.2) | Protects AC-14 and the CI pipeline from tag hijacking | Guard dry-run locally (passes on current tree) |
| S8 | ADR-009: no proxy in 1.0 | Keeps the app backend-free and the privacy label empty | Decision |

Secret scan of the Release binary: no API-key-like strings.

## 5. Performance

All numbers on the Mac test host (Apple silicon). Release figures use `swift test -c release -Xswiftc -enable-testing`.

| Measurement | Before | After | Budget |
|-------------|--------|-------|--------|
| First launch: open stores, import bundled library | 82 ms | 73 to 96 ms | < 1.5 s |
| Warm launch: open stores, content current | 21 ms | 16 to 28 ms | < 250 ms |
| Dashboard, 20 000 attempts, release | 56 ms | 48 to 56 ms | < 100 ms |
| Dashboard, 20 000 attempts, debug | 155 ms | 133 ms | < 400 ms |
| Dashboard fetch of all attempts, release | 60 ms | 35 ms | — |
| Dashboard statistics, release | 39 ms | 20 ms | — |
| Vocabulary search, 10 000 words | 58 ms (Phase 9) | 70 to 79 ms | < 150 ms |
| Answer feedback | < 1 ms | < 1 ms | < 100 ms |

What changed:

- `allAttempts()` fetches with `returnsObjectsAsFaults = false`: one pass over the row data instead of a fault per object. A dictionary-result fetch was tried and was slower (102 ms) because of bridging, so it was not kept.
- `ProgressStatistics.summary` keeps the current day's `DateInterval` (`DayBuckets`) and calls the calendar only when an attempt falls outside it. Same result as `startOfDay` for any order of dates and across DST; `DayBucketsTests` checks both.
- Not changed, measured and judged unnecessary: skipping the content decode when the installed version is current (warm launch is already 16 to 28 ms; avoiding it would need a model change), and Core Data indexes (every hot predicate already has one).
- Search shows run-to-run spread between 58 and 79 ms; no code on that path changed.

Instruments hooks: `AppContainer` emits `os_signpost` intervals `OpenStores` and `InstallContent` (subsystem `com.nemsothea.hangustep`, category `Launch`) for the AC-13 device measurement.
